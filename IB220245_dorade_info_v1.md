# IB220245 - Implementation Documentation

This document describes the changes made to implement the background runner/worker with NoWork output functionality.

---

## 1. Background runner / worker with NoWork output

### 1.1 What the behavior was before

**Before the changes:**
- The agent was executed only when the user clicked the "Get Coffee Recommendation" button in the Streamlit UI
- The button directly called `agent.act()` method
- There was no autonomous execution loop
- If the user did not interact with the UI, the agent did not run at all
- The agent had no concept of "no work" state - it would always generate a recommendation when `act()` was called

**Location in code:**
- File: `streamlit_app.py`
- Line: 252-254
- Code:
  ```python
  if st.button("☕ Get Coffee Recommendation", type="primary", use_container_width=True):
      recommended = st.session_state.agent.act()
      st.session_state.current_recommendation = recommended
  ```

### 1.2 What the behavior is after

**After the changes:**

**a) Autonomous background runner:**
- A background worker runs independently of the Streamlit UI
- The worker starts automatically when the application starts
- It runs in a separate daemon thread
- The Streamlit UI is no longer responsible for triggering the agent logic
- The agent can operate autonomously even without any user interaction

**b) tick()-based execution:**
- The agent now has a `tick()` method that processes exactly one decision/recommendation per call
- The background runner periodically calls `tick()` (every 2 seconds by default)
- The previous direct execution via `agent.act()` from the UI button is replaced with queue-based requests
- Users can request recommendations by adding context to a queue, which the background worker processes

**c) NoWork output/state:**
- An explicit `NoWork` class has been introduced
- `NoWork` is returned when:
  - There is no new user context in the queue
  - Not enough time has passed since the last recommendation (minimum 5 seconds)
  - There is a pending recommendation waiting for user rating
- This makes it explicit that the agent is running but currently has no task to perform

**d) Streamlit UI role:**
- The Streamlit UI remains for:
  - User input (context settings, rating submissions)
  - Displaying recommendations generated by the background worker
  - Showing agent state and statistics
- Agent execution no longer depends on UI button clicks
- The system operates autonomously in the background even without user interaction

- **File:** `brewbuddy_agent.py`

  - Processes one context from queue if available
  - Generates recommendation and updates tracking variables
  - Returns the recommended coffee string

## Summary

The implementation successfully introduces:
1. ✅ An autonomous background runner that operates independently of the UI
2. ✅ A `tick()` method that processes exactly one decision per call
3. ✅ An explicit `NoWork` state that indicates when the agent has no work to process
4. ✅ Queue-based context requests instead of direct UI-triggered execution
5. ✅ The ability to run the agent autonomously without any UI interaction

The agent now runs continuously in the background, processing recommendations from a queue, and explicitly communicates when it has no work to do.
